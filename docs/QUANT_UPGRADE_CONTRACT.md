# Quantitative upgrade contracts (v2)

The legacy indicator/API shapes remain compatible. New shared strategy rules drive current setups and historical validation. No live current financial/news/macro snapshot is reused in historical decisions.

## Completed-bar and feature contract
`analysis/features.py` (root): `build_features(history, benchmark=None)->pd.DataFrame` computes causal daily indicators once. `snapshot_at(features,index=-1)->dict` reads only through that position. Fields: as_of,close,open,high,low,atr,rsi,rsi_previous,sma_20,sma_50,sma_200,ema_21,slope_50,slope_200,adx,atr_percentile,hv_percentile,historical_volatility,relative_strength_63,benchmark_trend,structure ('higher_highs_higher_lows','lower_highs_lower_lows','mixed'),support_zones/resistance_zones list{price,touches,confirmed_at,lower,upper},support,resistance,swing_high,swing_low,prior_high_20,prior_low_20,range_atr_20,relative_volume,bollinger_lower,bollinger_upper,previous_close,previous_low. Missing numbers null, not favorable defaults. Confirmed pivots require two later completed bars. No final full-sample levels in earlier snapshots.

`analysis/regime.py`: `classify_regime(features:dict)->dict` outputs regime,trend_strength,volatility_regime,confidence,evidence:list[str],features,limitations:list[str]. Exact labels Strong bullish trend / Weak bullish trend / Sideways consolidation / Weak bearish trend / Strong bearish trend / High-volatility regime / Insufficient Data. Root snapshot provides above feature names. Optional wrapper `analyze_regime(history,benchmark=None,as_of=None)` can lazily import root build_features/snapshot_at, then classify; no duplicated formula needed.

`analysis/timeframes.py`: `analyze_timeframes(frames:dict[str,pd.DataFrame],metadata=None,as_of=None)->dict` keys weekly,daily,4h,1h,15m; output timeframes:list[{timeframe,status,trend,momentum,volatility,support,resistance,bars,last_bar_at,source,limitations}],alignment,confidence,limitations. Every frame may have `Bar End` timestamps in UTC; filter Bar End<=as_of, no unconfirmed candle used. If absent, conservatively exclude current source-local day/week or infer intraday duration and disclose. Root provider will supply explicit completion metadata and 4h session anchors. Do not count overlapping frames as five independent votes.

## Shared strategies and execution
`analysis/strategies/__init__.py` (root): `evaluate_strategies(snapshot,context,config)->list[dict]`. Four files trend.py,breakout.py,mean_reversion.py,value.py each evaluate same signature and return stable ids trend_following,breakout,mean_reversion,fundamental_value.

Context: regime result; fundamentals and valuation (current only); macro and earnings event-risk; timeframe alignment; live flags stale/incomplete; historical=True disables current financial/news/macro (value unavailable). Config: capital,risk_per_trade,risk_tolerance,horizon ('short','swing','long'),min_reward_risk,commission_bps,slippage_bps,max_holding_bars, existing_shares optional. Setup output id,name,status ('eligible','wait','avoid','insufficient_data','not_applicable'),eligible bool,entry_condition,entry_zone:[low,high]|null,entry_reference,stop,targets:[float] up to3,net_reward_risk:[float],risk_reward(first),position_size,holding_horizon,max_holding_bars,evidence:list[str],avoid_reasons:list[str],invalidation{price,kind:'technical'|'thesis',condition},target_methodology:list[str],calculation:list[str],regime. Costs/levels fixed before eligibility; risk and affordability use worst entry and adverse execution. Setup status eligible means specified completed-bar confirmation already observed, next-bar execution still conditional on zone/risk.

`analysis/execution.py` (root): `calculate_execution(entry_zone,stop,targets,config,existing_price=None)->dict` rounds first, rejects invalid ordering; uses buy entry*(1+s)*(1+c), stop proceeds stop*(1-s)*(1-c), target proceeds target*(1-s)*(1-c). Per-share loss=entry outlay-stop proceeds; gain=target proceeds-entry outlay. Shares=floor(remainingrisk/unitloss) capped by remainingcapital/entryoutlay. No resizing stops/targets to meet R/R. Fixed validation is first-target full exit, not target ladder.

## Statistical validation (agent)
`validation.py`: `validate_strategies(history,config,benchmark=None)->dict` strategy results keyed stable ids. Use root features and evaluate_strategies on each point-in-time snapshot. Long-only, next open inside proposed zone (no cherry-picked later touch), static original stop/target1, max holding, commission/slippage, no overlap per strategy, gaps against stop filled adverse open, simultaneous stop/target stop first. Exclude current financial value/news/macro; value report Insufficient historical evidence. Root shared regimes use causal snapshot.

Output strategies:{id:{status,sample_size,metrics,equity_curve,trades,out_of_sample,walk_forward,sensitivity,probability_records,limitations}}, benchmark,methodology,limitations. Metrics include trade count,win_rate,average_gain/loss,expectancy,cost-adjusted return,maxdrawdown,Sharpe,holdingperiod,MFE/MAE. Trades preserve as_of signal_time,entry_time,exit_time,regime,target1/target2/stop outcomes,net_return,holding_bars,mae,mfe,exit_reason. Probability records must be nonoverlapping, include timeouts as unresolved third outcome, and be closed before current candidate as_of. Dataset split70/30; purge any training outcome overlapping split; no parameter tuning on holdout. Fixed heldout walkforward and modest cost/threshold sensitivity, no claim fitted ML. Confidence intervals/minimumN required for inferential display; raw descriptive metrics may appear with weak-evidence label.

`probability.py`: `estimate_probabilities(records,candidate,as_of=None,min_samples=30)->dict` filter same strategy/regime/horizon and comparable stop/ATR/target R bins fixed before outcomes. Prefer heldout records. Return status ('available'|'Insufficient historical evidence'),sample_size,min_samples,validation_period,estimates:{target_1_before_stop,target_2_before_stop,stop_before_target,expected_return,expected_holding_bars},confidence_intervals,limitations. Missing/inadequate target2 has its ownN/status; never substitute arbitrary0.5. Wilson95% intervals for binary event frequencies; target1/stop/unresolved denominators disclosed; conditional target2 separatelytracked instead of pretending first-target trade continues. Probability metadata must distinguish empirical historical frequency from calibrated forecast. No LLM probabilities.

## Frontend/API (root integration, agent frontend)
GET /api/stocks/{ticker}/quantitative?horizon=swing&benchmark=SPY and POST same path with QuantRequest (TradeRequest fields plus commission_bps,slippage_bps,benchmark_ticker,min_samples,max_holding_bars,valuation_assumptions optional) return:
{ticker,as_of,methodology_version:'2.0',regime,timeframes,strategies:list,recommendation:{recommendation,best_strategy,entry_zone,stop,targets,risk_reward,position_size,entry_condition,calculation,invalidation,event_warnings,limitations},probabilities,validation,scores:{company_quality,valuation_attractiveness,technical_strength,trade_setup_quality,macroeconomic_environment,overall_investment_attractiveness,weights,contributions},evidence:{confidence,data_freshness,model_uncertainty,sample_reliability,limitations},valuation,event_risk,source}.
Each named score is float|null. Existing research payload gets cheap quant_core with regime/strategies/newscoring/plan; expensive intraday/statistical retrieval only explicit quantitative endpoint with persistent cache. Main UI uses new core plan+scores while advanced section adds full validation context. Legacy score interface retained via adapter for old clients, methodology version explicit.
