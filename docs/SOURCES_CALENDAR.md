# Economic calendar sources and historical validation

Verified against the official Forex Factory [Calendar](https://www.forexfactory.com/calendar) and [Notices / Terms of Service](https://www.forexfactory.com/notices), accessed October 25, 2026 (America/Los_Angeles).

The Calendar page has a Weekly Export area linking ICS, CSV, JSON and XML. These are website export features, not a documented unrestricted public API. Its notices reserve rights in the assembled economic database, including calendar schedules, and restrict copying and redistribution without permission. The presence of export links alone does not establish permission for automated ingestion or redistribution. EquityLens therefore implements an **import-only** `ForexFactoryCalendarProvider`: obtain and use a file only within your authorization and the applicable terms, then import it privately. No scraper, anti-bot bypass, export downloader or background network calendar polling is provided. Calendar source records are never included in distributable demo fixtures; tests use synthetic events clearly named Synthetic.

## Import

POST `/api/economic-calendar/import` with `content` containing an authorized export, `format` (`json`, `csv`, `xml` or `ics`), and `source_timezone` (IANA zone, default `America/New_York`). The JSON reader accepts a list or an `events` list. CSV accepts common title/name, currency/country, date/time, impact, forecast, previous and optional actual columns. XML accepts the weeklyevents/event shape. ICS supports DTSTART with UTC or TZID, SUMMARY, DESCRIPTION numeric fields when present, and all-day events. Not every export contains every field. Unsupported or absent actual/revision values remain null; ranges cannot be treated as single numeric values.

All dated release times are converted to UTC. Naive ambiguous or nonexistent daylight-saving local times are rejected: import an explicit offset to resolve them. All-day, tentative and unknown times retain their date without inventing midnight release times. Country/currency labels are preserved as supplied; Forex Factory's `country` field may contain a currency code. K/M/B/T amounts expand to base units; percentages remain in percent units so a difference of 0.2 is **0.2 percentage points**, not 20 percent. Source IDs, when supplied, remain stable across reschedules and cancellations. Otherwise title/currency/scheduled-time identity and last-updated timestamps deduplicate repeat imports and prefer later revisions. Without source IDs, changed release times cannot reliably be matched to old records; replace the imported calendar snapshot or remove the superseded record rather than assuming it is a new independent event. Parser input is limited to 2 MB and 10,000 events, and XML entities/document types are rejected.

`CalendarProvider` is a replaceable Python protocol. A separately authorized API can implement the same normalized event schema, but its licensing, limits and availability timestamps must be assessed independently. EquityLens makes no claim to retrieve 30 days if the imported weekly file covers fewer days.

## Surprise and macro interpretation

`actual - forecast` is calculated only for comparable units and known past releases. Future actual values, delayed/canceled releases, future last-updated revisions and future availability timestamps do not enter the interpretation. If ten or more prior comparable, availability-timestamp-verified releases are supplied, normalized surprise = current forecast error / sample standard deviation of prior forecast errors. Otherwise normalized surprise stays null.

Inflation above consensus is labeled potentially bearish for rate-sensitive valuations, while labor surprises are mixed because policy and demand effects can conflict. For financial firms, inflation/policy surprises are mixed because funding costs, margins and credit losses can respond in opposing directions. These are conditional hypotheses. No price reaction or causal attribution is inferred. Upcoming high-impact events raise anticipated event risk, not historical volatility. Event-risk strategy windows are one day for short-term, three for swing and seven for long-term; the response also supplies 1/3/7/30-day windows. Missing imported coverage is explicitly reported.

Macro scoring uses recent available releases, grouped as inflation, policy and activity to limit double-counting. A group averages conditional direction (+1 bullish, 0 mixed/uncertain, -1 bearish). Score = 5 + 2 × average of available group averages. The bounded 3–7 range and confidence ceiling of 0.55 reflect the heuristic sector linkage and absent policy-futures/geographic exposure evidence. No recent comparable releases yields no score. This component describes a conditional environment for the stock; it does not change management-quality evidence.

## Price-only backtest

The implemented strategy is a long-only SMA crossover with configurable periods and a fixed stop at prior completed close minus twice 14-bar **simple** ATR. All close-time signals execute at the following bar's open. Stops execute at the stop or a worse opening gap, with explicit slippage and commissions. Position sizing includes modeled stop slippage and entry/exit commissions in its risk budget and is capped by available cash. Gaps can exceed target risk. Final positions are liquidated with costs.

Yahoo split-adjusted OHLC is required; where `Adj Close` exists, its ratio to Close adjusts all OHLC consistently for a total-return proxy. Trade quantities are adjusted units, not literal historical shares. OHLC consistency, duplicate dates, missing and non-positive prices are validated. Weekends/closures are not inserted. Buy-and-hold and supplied index benchmarks use the same evaluation dates, starting capital and execution-cost assumptions. Missing exact-date index coverage yields an unavailable benchmark.

The last 30% is separately evaluated with fixed parameters and fresh capital when at least 30 evaluation bars exist. Three chronological holdouts are also provided when each contains at least 30 bars; these are fixed-parameter stability checks, not optimized walk-forward fitting. Earlier prices provide indicator warmup only. No parameter search is performed.

Only past price bars drive this backtest. **Fundamentals, company news and macro data are excluded**, because current/revised snapshots and an imported weekly calendar do not establish historical point-in-time availability. A future extension must store original release, forecast revision and actual-availability timestamps before it can test macro-conditioned decisions. The backtest does not use any calendar input, even if supplied in its config.

Metrics: total return = ending equity / starting equity − 1; annualized return uses 252 sessions/year; drawdown is the minimum equity / prior running peak − 1, including initial capital; Sharpe uses daily equity changes with a zero risk-free assumption; win rate counts completed positive-P&L trades / all completed trades; average gain/loss are currency P&L; profit factor is gross positive P&L / absolute gross negative P&L, null if there are no losing trades. Historical results do not estimate guaranteed future performance.
